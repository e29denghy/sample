# denghy.cn 写作原则

适用公开网页和文章，更新于 2026-09-06。

读者是正在做 AI 应用、教育产品和 Web 项目的同行。首页先说清作者做什么，技术文章为正在解决类似问题的人提供材料和判断。

口吻采用平实的第一人称。用真实项目解释观点，让读者看见选择和理由。亲历、情绪、对话和动机必须来自作者提供或确认的素材；缺少素材时直接从问题或事实开始。

1. 写作前用一句话确定主要问题和判断，列出依据与缺口。
2. 每段推进一个意思。步骤、并列结果和参数比较需要时才用列表或表格。
3. 用动作解释抽象概念：“每次重试单独记录，保留第一次失败的原因”，比“构建可审计闭环”更容易理解。
4. 保留影响判断的技术机制、数据口径与限制，解释它们为什么有用。完整环境和测试记录可放文末。
5. 检查重复的对比句、“真正的”“这意味着”“值得注意”等表达。根据意思修改，不机械禁词或增加口头禅。
6. 标题给出对象和问题，摘要补充阅读所得，开头继续推进，不连续复述。
7. 区分厂商声明、资料分析和作者实测；版本、发布日期、许可证与可用范围分别核对。
8. 结尾落在实际结果、未解问题或有依据的后续选择，无需固定总结条数或宏大比喻。

实践文讲一次选择及后果；教程提供复现和排错；趋势文展开证据与判断；近况只写确认的正在发生的事。旧有八项案例要素作为内部检查表，不要求成为固定章节。

审稿顺序：核对事实 → 调整内容顺序 → 删除重复表达 → 连读标题、摘要和开头 → 朗读。检查是否保留项目特有的例子，并确认作者愿意用这些话向同行解释工作。

依据：[OpenAI 官方写作指南](https://developers.openai.com/api/docs/guides/latest-model#gpt-6-astra-personality-and-writing-style)，2026-09-06 重新读取。中文规则为本站编辑约定。
