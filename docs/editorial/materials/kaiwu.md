# 开物：材料清单

日期：2026-09-06。题材：项目实践，面向接入 AI 编程工具的 Web 开发者。

来源：[已发布文章](https://denghy.cn/articles/kaiwu-deepseek-harness-human-approved-adapter)、`database/content/kaiwu-deepseek-harness-adapter.md` 及公众号文件。本地 Markdown SHA-256：`c0c3c5055cbe30c9c699c6aceeb8e7914f7549d8e6dac3bf56bc0862ac72cd9f`。生产文章 ID 10、修订 ID 15；历史时点为 2026-08-29。本轮未重跑 KAIWU 项目测试。

主要问题：网页上的任务获批后，怎样交给 DeepSeek Harness 执行，并在失败重试后查清每次结果。

已有判断：网页保存目标和批准信息，独立进程执行；批准信息需要重新检查，重试保留第一次失败。

| 保留事实 | 原文位置 | 编辑用途 |
| --- | --- | --- |
| Bridge 消费批准后的 Outbox，执行后写回 Inbox | 职责分工段 | 用一个任务的流向解释进程分工 |
| Quest 包含 ID、目标、约束、写入要求和批准信息 | 协议段 | 首次提到术语时解释，避免集中堆砌 |
| 缺少批准信息拒绝执行，只读和写入分别映射权限 | 权限映射段 | 展开实际校验行为 |
| 事件已落库但投影失败，重复同步修复状态 | 重试段 | 保留失败机制和幂等的实际作用 |
| SDK wheel 无法加载沙箱插件，CLI 要补 peer 依赖 | 版本适配段 | 解释固定可安装且验证过的 CLI 的原因 |
| 验证未调用真实模型，也未使用 API Key | 验证范围段 | 必须保留，不能写成模型端到端质量评测 |

CLI `0.1.1-rc.2`、SDK `0.1.1rc1`、源码标签与提交哈希放入“2026-08-29 的版本记录”，不称为今天的最新版本。

缺口：真实模型任务的质量、时长和费用没有测试材料；当前安装包版本需第三阶段涉及升级时重新核对；作者希望先用来完成什么任务尚无明确素材，不编造使用频率和生产收益。批准与审计设计不能推出所有风险都已消除。

候选标题：开物接入 DeepSeek Harness：任务批准后怎样执行。尚未替换线上标题。
