# 从 DeepSeek Harness 原型到生产站：福宝实时英语对话上线实录

> 一个能实时对话的原型，距离可以放到公网给人使用，中间还隔着准入、配额、密钥、隐私、部署和真实链路验证。这次我把用 DeepSeek Harness 开发的 Voice 整合进 Fobo，并把它发布到了独立测试站。

![福宝实时英语对话测试站：邀请码换取设备通行证](https://denghy.cn/images/articles/fobo-realtime-voice-release/00-realtime-access.jpg)

上线地址：<https://voice.denghy.cn/talk>

目前站点采用邀请测试，不公开发布邀请码。

## 这不是一次简单的“复制页面”

Fobo 原来是一个小而简单的英语角：五个主题、六个快捷句型，一次请求得到一次文字和语音回复。它重点解决的是“听见、开口、得到反馈”这个最小练习闭环。

Voice 则已经有实时 WebSocket 对话、字幕、打断、场景、会话、配额、录音和管理端。两边都是 Laravel 和 Vue，但产品边界、状态模型和运行依赖完全不同。

![实时语音测试页提供六个教材场景，当前选中 U3 寻找玩具](https://denghy.cn/images/articles/fobo-realtime-voice-release/02-scenario-gallery.png)

实时入口不是一个空白聊天框。测试版提供五感魔法秀、家庭聚会、寻找玩具、我家附近、农场之旅和中秋节六个场景，每个场景带有词汇、句型和难度提示，孩子点击卡片即可开始。

![原 Fobo 英语角：首页、主题与快捷句型继续保留](https://denghy.cn/images/articles/fobo-realtime-voice-release/01-original-english-corner.jpg)

所以整合前先做 Review。

两个项目的既有测试和构建都能通过，但 Review 仍然找出了六个不能直接带进生产的问题：本地 Relay 依赖开发机证书和端口；管理端认证不适合公网；配额可以被并发会话绕过；费用数据来自浏览器；WebSocket 缺少连接和消息约束；Voice 的狐狸形象与 Fobo 小熊猫品牌不一致。

原 Voice 数据库中的访客、会话、字幕和约 86MB 录音全部留在原项目，没有进入生产站。

## 最终架构：同域分流，各做一件事

最初评估过托管 Site 加个人服务器 Relay。比较 Cookie、跨域、WebSocket 和维护成本后，最终采用个人服务器全栈、同域分流：

```text
https://voice.denghy.cn
        │
        ▼
      Nginx
        ├─ /ws      → Node Relay → Qwen Realtime
        ├─ /build   → Vue 静态资源
        └─ 其他请求 → Laravel / Inertia
```

Nginx 统一处理 HTTPS，Laravel 负责邀请码、通行证、配额和会话，Node Relay 只负责实时转发和供应商用量回传。

浏览器拿不到 Qwen 的长期 API Key。Relay 只监听服务器回环地址，公网只能通过 Nginx 的 `/ws` 进入。

## 不注册账号，也要控制实时语音费用

孩子端如果先要求注册和登录，使用门槛会很高；但完全匿名公开实时语音，又会让费用失控。

最后采用四层准入：

```text
邀请码
  ↓ 首次兑换
设备通行证
  ↓ 开始会话
服务端原子预占配额
  ↓
60 秒单次 Relay 票据
  ↓
Qwen 实时会话
```

邀请码只保存 HMAC 摘要，不保存明文。兑换后，设备得到 Secure、HttpOnly 的通行证，孩子不用反复输入邀请码，前端脚本也读不到通行证内容。

开始语音前，Laravel 在事务里检查并预占单次、每日、总时长和并发额度。没有真正连上 Relay 的会话会释放额度，正常结束则按服务端时间结算。系统还设置全站每日时长和月度预算熔断。

通过配额门槛后，Laravel 才签发大约 60 秒有效、只能使用一次的 Relay 票据。Relay 校验签名、有效期、Origin、会话和 nonce。供应商 Token 用量由 Relay 回传，浏览器提交的用量不再被信任。

第一版默认关闭录音。前端不上传音频片段，日志也不记录完整票据、音频或 API Key。

## 上线过程，每一步都有停止条件

整合前先给 Fobo 建立可回退的 Git 基线，并把 Voice 来源固定在干净提交 `c3553e0`。迁入的是实时语音能力和必要测试，不是原项目的环境文件、数据库和录音。

本地发布门最终全部通过：

- PHP：24 个测试、141 个断言；
- 前端：30 个单元测试；
- TypeScript 检查和 Vite 生产构建；
- Relay 模拟上游转发和非法 Origin 拒绝；
- SQLite 迁移、全量回滚、再次迁移和场景播种；
- Git 树密钥与录音检查。

服务器阶段先做只读盘点。盘点发现，正确主机没有宿主机 PHP 和 Node，并且内存有限。因此没有临时安装全局运行时，而是使用两个相互隔离的 Docker 和 systemd 服务：Laravel 监听 `127.0.0.1:9086`，Relay 监听 `127.0.0.1:9333`。

部署使用经过校验的 Git Bundle 和前端制品。上传前后核对 SHA-256，生产 checkout 只做快进更新，数据库、环境文件和服务配置先备份再变更。

TLS 先启用只响应 ACME challenge 的 HTTP 引导站点。确认 DNS 正确、挑战文件返回 200 后才签发证书，再切换最终 HTTPS 配置，并补上证书续期后的 Nginx reload 钩子。

生产最终提交为 `ab055fc`。

## 200 不是实时语音的验收终点

页面返回 200，只能证明 HTML 可以打开。

这次生产验收继续走完了真实链路：

- 无设备通行证访问语音 API，返回 401；
- Relay 健康检查正常，且只监听回环地址；
- 真实 Qwen 上游返回 `session.created`；
- 同一个 Relay 票据再次使用，返回 403；
- 60 秒测试会话自动结束，并准确结算 60 秒；
- HTTP 正确跳转 HTTPS，证书自动续期正常；
- `/ws` 关闭访问日志，三类服务日志未发现密钥或票据泄露。

代码测试、浏览器截图和真实上游会话证明的是不同问题，不能互相替代。

## 这次上线留下的四个结论

第一，Review 不是评价原型好不好，而是找出哪些假设只在开发机成立。

第二，实时语音安全应该围绕短时票据和服务端配额建立，而不是围绕隐藏前端参数建立。

第三，默认不录音、原子预占、硬超时和预算熔断，应当在第一次公开测试前就进入架构。

第四，完成必须由证据定义。测试、构建、迁移闭环、TLS、真实上游事件、票据重放、结算回读和日志审计一起通过，才算真正上线。

现在，原 Fobo 英语角仍保留在首页，实时英语对话作为独立入口运行在 `/talk`。

它还处在邀请测试阶段，但已经从“能在开发机说话”的原型，变成了一套可以控制访问、费用、密钥、隐私和故障边界的生产系统。
